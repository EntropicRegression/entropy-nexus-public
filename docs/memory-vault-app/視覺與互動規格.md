# Entropy Nexus 記憶寶庫(管理 App)視覺與互動規格書

> **詳細視覺以管理 App repo 的 `DESIGN.md`(v9 + 2026-11-22 裁示)為準**:管理 App 是獨立 repo(本機 `entropy nexus mind vault`),色票、字級、元件尺寸、動畫數值都在那裡。本文件是主控台這一側的摘要,讓兩邊對同一份記憶庫的理解一致;兩者不一致時以 `DESIGN.md` 為準,並回頭修本文件。
> **定案日期**:2026-11-21 初版;2026-11-22 依管理 App 的 v9 設計與使用者裁示同步(來源:管理 App repo `docs/主控台規格同步清單.md` 22 條)。
> **參考互動原型**:`互動原型.html`,只留在本機的這個資料夾(已列入 .gitignore,不放進 repo),因為它引用未公開的角色美術。它是樓上星圖的原版;樓下已由 v9 取代。
> **對接後端規格**:`docs/記憶設計討論.md`(第二輪定案 13 點、第三輪「管理 App 定案」)與 `docs/任務清單.md` 階段 4.5 / 階段 5。
> **技術選型(已確認)**:electron-vite、React 19、TypeScript strict、Vitest、electron-builder(NSIS)。星圖用 CSS 3D + 手寫投影 + Canvas 2D,不需要 Three.js。

## 一、整體空間架構與視覺語言

1. **上下兩層,垂直攝影機**
   * **樓上「星象召喚盤」**:節點休眠庫(3D 星圖 + 角色水晶 + 履歷欄),沿用原版互動原型。
   * **樓下「典藏室」**:判例模式(待核閱案頭 + 篩選列 + 藏書架 + 閱讀桌)。啟動時停在樓下。
   * 固定視窗的桌面 App,基準 1600×900、最小 1280×760;整頁不捲動,只有內容區各自捲動。

2. **樓層切換**(取代舊的「穹頂 / 天窗傳送門」概念)
   * 鏡頭垂直平移 100vh,980ms、ease-in-out cubic。
   * 只模糊 Y 軸(垂直動態模糊),中段最大約 14px,結束時清除;輕微傾斜 rotateX ±2.4°;樓下背景視差 0.35。
   * 兩層頂列在進度 45% 時交叉淡換;動畫中再點直接跳到終態;星點拉長往下流。
   * 低動態(系統「減少動態」或 App 的低動態開關):不平移不模糊,改為 ≤150ms 淡換。
   * 入口:兩層頂列各有樓層切換;樓上舞台底部保留「▼ 向下俯視,回到大圖書館判例卷宗室 ▼」天窗標籤。

3. **兩層各自的視覺語言**
   * **樓上**:原版星圖的遊戲介面語言(45° 切角外框、細描邊、冷色系),只限樓上使用。
   * **樓下**:深藍夜色 + 暖木書架 + 奶油紙卡 + 襯線字;內容一律在紙面上,不用大色塊與發光徽章。亮金只給「現在」(焦點、選取、主按鈕)。
   * **狀態只在寫入成功後改變**:按下後顯示「正在寫入…」,成功才改狀態、落印、更新計數;失敗顯示「未儲存」與「重試」。

## 二、樓下「典藏室」(判例模式)

* **背景**:`library-starry.png`(星夜書閣,原創素材)疊夜色暗幕。
* **待核閱案頭**(最上方,單列便箋,超過 4 張橫向捲動):
  * 收錄所有 `狀態: 未確認` 的記憶(判例、決策、典藏的知識與偏好草稿)與 `狀態: 未完` 的書籤,新到舊。
  * 每張便箋「看詳情」+ 主按鈕「確認」(書籤為「標為完成」);**寫入成功後**才落低飽和小印記並更新計數。
* **篩選列**:頁籤「全部 / 判例 / 決策 / 書籤 / 典藏 / 待處理」+「書閣」(依專案)+ 結果數「凡 N 卷」。「待處理」= 未確認或退回(書籤則為未完)。
* **四個書架**(一筆只屬一個書架):

  | 書架 | 收錄 | 卡片外型 | 識別 |
  |---|---|---|---|
  | 判例 | `cases/` | 書脊 | 案號(`2026-0003`) |
  | 決策 | `knowledge/`,`子類: 決策` | 摺頁 | 不編號,「決策 · 日期」 |
  | 書籤 | `knowledge/`,`子類: 書籤` | 籤條 | 不編號,「書籤 · 日期」 |
  | 典藏 | `knowledge/` 其餘(專案知識)+ `preferences/` 全部(使用者偏好) | 題簽框 | 不編號,「典藏・知識 · 日期」/「典藏・偏好 · 日期」 |
  | (不上書架) | `nodes/` 節點側寫與封存 | — | 只在樓上水晶履歷呈現 |

* **卷宗卡**:中繼列(識別 · 狀態)→ 標題(最多 2 行)→ 摘要(最多 2 行)→ 底列(左熱度,右頭像章與「前版 ×N」)。
  * **狀態** = 菱形 + 短字:待核閱(空心)、未完書籤(空心)、已收錄(實心)、已完成(實心)、已退回(空心加斜線)。沒有 `狀態` 欄位的舊檔或主控台直接寫入的知識/偏好視同已收錄。
  * **「前版 ×N」**:有取代鏈才出現;點開的浮層疊在卡片下方,不推擠書架。
* **熱度**(讀記憶庫根目錄 `.nexus-heat.json` 的召回次數):紙面明度四階 + 3 顆**不發光**的小晶石 + 文字。

  | 代號 | 名稱 | 召回次數 | 晶石 |
  |---|---|---|---|
  | `ember` | 餘燼 | 0 | 0 顆亮 |
  | `tepid` | 微溫 | 1–2 | 1 顆 |
  | `temperate` | 溫潤 | 3–4 | 2 顆 |
  | `flaming` | 炙熱 | ≥ 5 | 3 顆 |

  最後一次召回超過 30 天降一級(最低餘燼;沿用先前預設,可調)。舊名稱「沉睡/餘溫/微溫/熾熱」與門檻 0/1–2/3–6/7+ 已廢止(「微溫」一詞保留,但改指 1–2 次)。只有 agent 呼叫 `memory_read` 才算召回;管理 App 開卷不算,也不寫熱度檔。

* **節點頭像章**(卡片底列右側):
  * 20px 圓,最多 3 枚 + `+N`;承辦節點(`節點ID`)在前,其後是 `參與節點ID`(去重、排除承辦)。
  * 圖像經 `vault-image://node/<節點ID>/avatar` 讀本機美術(見第四節);沒有頭像改用首字徽章;節點不在星圖上時徽章改虛線、不可點。
  * 懸停顯示「承辦:名稱」或「參與:名稱」;點擊不開卷,改為飛往樓上並選中該水晶。鍵盤使用者改用閱讀紙中繼列的節點名稱連結。

* **閱讀桌**(兩種版式,頂列可切換,**記住使用者上次的選擇**,首次啟動為 A):
  * **A 寬幅閱讀桌**:蓋住頂列以下的舞台,紙置中;點紙外或 Esc 關閉。
  * **B 右側 420px 欄**:書架同時可見,可繼續用方向鍵瀏覽。
  * **閱讀紙**內容:中繼列(識別 · 類別 · 專案 · 狀態 · 熱度 · 日期 · 承辦/參與名稱)→ 結論摘要 → 正文(最寬 38em)→ **回顧**(正文之後的小節,讀檔案最後的 `## 回顧`;沒有就不顯示)→ 側欄「取代演化線」「關聯卷宗」。
  * 頁尾:「確認 / 標為完成」「退回」「移入回收」+ 寫入訊息(失敗為「未儲存」+「重試」);移入回收可撤銷。

## 三、樓上「星象召喚盤」(節點休眠庫)

* **3D 星圖舞台**:節點與渾天儀在 3D 座標裡,依深度計算透視、前後與淡化。拖曳旋轉每 px 0.007 rad,pitch 限 ±0.95;滾輪縮放 0.65–1.65;拖曳超過 3px 不觸發點選;停在最後角度,不自動旋轉。
* **角色水晶**(原版:細長六角水晶,內含角色立繪):
  * 立繪一律經 `vault-image://node/<節點ID>/portrait` 本機協定讀取,不開 `file://`、不上傳。來源:現役節點是 `.nexus-stats.json` 的 `立繪路徑`;封存節點是 `nodes/封存/_圖像/<節點ID>/` 的快照。
  * 沒有立繪時顯示統一的星座線符(已定案:變體 C,對稱菱形星座)。
  * **位置依節點 ID 決定式自動擺放**:同一節點每次都在同一位置,新增節點不會讓其他節點移動(演算法見 `DESIGN.md` 6.4)。
  * **合併規則**:同一個 `節點ID` 的多份封存(「開啟舊 session」復原後再封存)合成同一顆水晶;「接回自」產生的新節點 ID 不合併,以傳承線相連。
  * 狀態徽章:「● 現役」(線上)、「● 休眠」、「✦ 封存 · 可喚醒」(`可接回: true`)、「◇ 封存 · 純紀念」。
* **水晶光暈 = 經歷豐富度**:白、綠、藍、紫、金、紅六級自動計算;第七級彩虹**只能由使用者手動頒發**,不會自動達成。
  * 計分只用使用者驗證過、或主控台客觀統計的資料:已確認判例(承辦/參與)、驗收數、退回數、完成數、跨專案數;不用文字長度、封存次數、任務總數。權重、上限、門檻與各級附加條件見 `DESIGN.md` 6.9(**建議值,使用者已同意方向,細節仍可調**)。
  * 頒發紀錄存在記憶庫根目錄的 `.vault-awards.json`(管理 App 專屬,見第四節)。
* **四種連線**(右上角開關兼圖例,可分別顯示/隱藏):

  | 種類 | 線型與色 | 來源 |
  |---|---|---|
  | 經驗傳承 | 金 `rgba(245,185,99,.85)` 實線 2.5px | 屬性 `接回自`(或「## 主控台補充」第一行) |
  | 交辦協作 | 青 `rgba(56,189,248,.65)` 虛線 1.8px | `.nexus-stats.json` 的 `協作` |
  | 會議同席 | 紫 `rgba(167,139,250,.68)` 點線 1.8px | `.nexus-stats.json` 的 `同席` |
  | 同專案 | 翠綠 `rgba(52,211,153,.48)` 長虛線 1.4px | 共同參與的專案 |

* **右側履歷欄**(只顯示濃縮版,不放逐字對話;沒有選取時收起):
  * 標頭:角色小字 + **經歷等級徽記**(與光暈同色的菱形 + 等級名,例「◆ 紫晶」;懸停顯示分數組成)。
  * 立繪框 + 名稱 + `角色 · 狀態` + 特長第一句 → 屬性條「任務完成率」「一次驗收率」+「累計完成任務 N｜經手判例 M」→ 濃縮解題流程 → 節點回顧 → 關聯卷宗(點擊切到樓下並開卷)→ 底部動作(喚醒、頒發/撤回彩虹)。
  * **節點側寫只在這裡呈現**,不上樓下書架。側寫全文閱讀、編輯、搜尋等缺口是否要補,**待使用者確認**(見 `DESIGN.md` 6.6)。
* **跨 App 喚醒**:`可接回: true` 時顯示「在主控台喚醒舊 Session」,確認後開啟 `entropy-nexus://wake?node=<節點ID>`,主控台會再跳一次自己的確認。
  * 系統拒絕這個網址(主控台沒安裝或沒註冊)時,提示「請在主控台用『開啟舊 session』接回」,並附名稱與 sessionId(可複製)。
  * 節點是否上線以下一份統計快照為準,不在 App 端假設成功。

## 四、檔案掃描與 Windows 跨進程安全約定

* 忽略記憶庫內所有 **`_` 開頭的附屬目錄**(`_圖像/`、`_回收/`)與 **`*.tmp`** 暫存檔。
* `.nexus-stats.json` 每個節點的專案有兩個欄位:`專案`(名稱清單)與 `專案ID`(同序同長度的專案識別;同名不同專案的 ID 不同)。跨專案數用 `專案ID` 去重;舊版主控台寫的檔案沒有 `專案ID`,退回用 `專案`。
* 讀取 `.nexus-heat.json` 與 `.nexus-stats.json` 時一次讀完即關檔;撞到寫入瞬間而解析失敗時保留上一份快取。`.nexus-*.json` 管理 App 只讀不寫。
* **`.vault-awards.json`**(記憶庫根目錄):管理 App 專屬的彩虹頒發紀錄。主控台**不讀、不寫、不刪,也不視為記憶**,記憶庫的 `說明.md` 也寫明請勿手動刪除(主控台的索引只掃 `nodes`、`cases`、`knowledge`、`preferences` 底下的 `.md`,根目錄的 JSON 本來就不會被索引)。
* **`vault-image://` 協定**:網址只帶代號(`node/<節點ID>/portrait`、`node/<節點ID>/avatar`),不帶路徑;管理 App 主程序依白名單解析成實際檔案:
  1. `.nexus-stats.json` 該節點的 `立繪路徑` / `頭像路徑`(主控台解析好的絕對路徑);
  2. 記憶庫內 `nodes/封存/_圖像/<節點ID>/` 的封存快照(主控台寫入的檔名是 `avatar.<副檔名>`、`portrait.<副檔名>`)。

  圖片只在本機讀取顯示;不寫進快取資料夾、不送到任何外部服務、不進 repo。
* 寫回記憶檔:暫存檔(同資料夾)+ 改名,改名前比對 mtime 與大小;主控台看到 mtime 改變會把檔案當成「使用者改過」,之後只附加不覆寫。
