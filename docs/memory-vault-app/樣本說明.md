# 記憶庫格式樣本說明

這個資料夾裡的格式樣本都是**去識別樣本**:節點、ID、專案、日期、路徑全是虛構的。樣本檔本身只放主控台實際寫出來的內容(逐位元組相同),不加任何說明文字,可以直接拿來當解析測試的輸入;說明都寫在這裡。請勿手改樣本檔,要更新就重跑產生工具。

| 樣本 | 產生工具 | 產生方式 | 實際寫入的路徑 |
|---|---|---|---|
| `回憶錄樣本.md` | `node tools/make-memoir-sample.mjs` | 用 `parseMemoir` 檢查參數,再用 `writeMemoir` 寫進暫存記憶庫,把寫出的檔案複製過來 | `memoirs/<節點名>-<節點ID 前 8 碼>/<YYYY-MM-DD>-<標題>.md`(同名時加 `-2`、`-3`) |
| `會議紀錄樣本.md` | `node tools/make-meeting-sample.mjs` | 用 `meetingRecordOf` 整理散會時的資料,再用 `writeMeetingRecord` 寫進暫存記憶庫,把寫出的檔案複製過來 | `meetings/<專案資料夾>/<YYYY-MM-DD>-<主題>.md`(同名時加 `-2`、`-3`) |
| `統計檔樣本.json` | 見 `docs/記憶設計討論.md` | 由 `buildVaultStats` 實際產生 | 記憶庫根目錄 |

## 回憶錄樣本的重點
- 第一行就是 `---`,檔頭字串一律用雙引號。
- 節點在參數裡填的 `節點ID` 被忽略,檔頭的 `節點ID`、`節點`、`後台` 由主控台依提交者填。
- 正文裡的本機絕對路徑換成「[本機路徑已隱藏]」,金鑰換成「[已遮罩]」。
- 產生工具故意把固定章節寫成 `## **來源**:`:主控台寬鬆接受這種寫法,寫進檔案時統一改成標準的 `## 來源`、`## 不確定之處`,所以樣本裡看到的是標準寫法。

## 會議紀錄樣本的重點
- 參與者不含主持人;主持人只寫在 `節點ID`、`主持人`。
- 略過的參與者記成第 0 輪;主持人結束時的結語成為「結論」,不重複列在逐字紀錄裡。
- 每則發言逐行加上 `> `。
