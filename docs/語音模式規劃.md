# 語音模式規劃

語音模式分成兩種用法:

- **語音輸入**:在某個節點的對話視窗按住「說話」,轉成文字填進輸入框,由你確認後送出。
- **主控語音模式**:直接對主控台說話,由「總管」節點判斷要交給誰並分派工作。

所有語音處理都在本機執行,不會把語音上傳到網路。也不能用語音回覆授權,授權一律在畫面上點。

## 進度

| 階段 | 內容 | 狀態 |
|---|---|---|
| Phase 1 | 語音輸入:按住說話 → 本機 faster-whisper 轉成文字 → 填進輸入框 | 完成 |
| Phase 2a | 可靠的語音播報:完成摘要、授權/提問/故障提醒、播放佇列 | 完成(待真實 CLI 實測與人工標記驗證) |
| 主控語音模式 | 總管區塊、全域語音、由總管節點分派 | 第一版完成 |
| Phase 3 | 每個節點有自己的聲音(CosyVoice 2) | 第一版完成(安裝見 `tools/voice-server/README.md`) |
| Phase 4 | 手機遠端語音 | 規劃中 |

## Phase 2a:可靠的語音播報

這份規格是 2026-11-19 和 chatty、哈gemi jr 開會討論後定案的。第一版不使用 Ollama 或其他本機 LLM,全部用規則處理。

- **什麼時候念**:主行程依任務結果決定(`src/main/core.ts`)。
  - 只有你從桌面發起的回合正常完成時,才念一句摘要。來源有四種,記在任務與佇列上:`desktop`、`remote`、`interop`、`autopilot`。
  - 節點正在跑別人交辦的回合時,你從桌面插話,這個回合就改算你發起的。
  - 被中斷的不念,包括後台自己取消(轉接器在待命事件上帶 `outcome: 'interrupted'`)。啟動或續接時的待命也不念。
  - 節點在等你授權或有問題要問你時,一定會提醒,不分是誰發起的回合。
  - 你從桌面發起的回合出錯或失聯時會提醒;排隊的指令被額度上限擋住時,第一次也會提醒。
- **念什麼**:摘要規則寫在 `src/shared/speech-summary.ts`,是純函式。
  - 先清理:拿掉程式碼、表格、堆疊、網址、超長識別符、過長的括號補充,路徑只留檔名。
  - 回覆夠短就直接念全文。太長時,從第一段第一句和最後兩段裡挑句子,優先序是要你決定的事、還沒解決的問題、已完成的成果。
  - 長度上限是 65 個朗讀單位,中文一字算 1,英文一個單字算 2。
  - 最後一則訊息沒有實質內容時,改看倒數第二則。都找不到能念的句子,就念「某某 完成了,詳情請看畫面」。
- **怎麼送**:經 `nexus:speech` 只推給桌面主視窗,不經過 `nexus:update`,所以遠端與節點互相呼叫的服務都拿不到。
- **怎麼播**:播放佇列在 `src/renderer/src/sound.ts`。
  - 授權和提問插隊,播之前會確認還在等。
  - 完成通知最多排 5 則,超過 60 秒就丟掉,同一節點只留最新一則。
  - 同一節點的故障提醒,60 秒內最多一次;最多同時排 2 則不同節點的故障,再有其他節點出錯,只在第 2 則後面補一句「另有其他節點異常」。
  - 每則都有逾時保護。錄音時暫停播報,被錄音打斷的完成通知直接丟掉。
- **驗收**:
  - `node tests/voice-summary.test.mjs`:摘要規則的單元測試。
  - `bash tests/voice-speech.sh`:假資料模式,實際檢查播報的時機與內容。
  - `node tools/voice-summary-backtest.mjs`:用本機資料庫裡的真實回覆跑一次摘要,報告寫到暫存資料夾,不會進版本庫。要驗證核心資訊命中率至少 85%,需要人工標記約 60 則,並保留至少 15 則到規則定案後才拿來驗證。

## 主控語音模式(第一版)

- **總管區塊**:在面板「執行 ACTIVE」那一列的最右側,綠色邊框。
  - 還沒指定總管時,區塊裡有一個「+」六角形。點下去會開啟「指定總管節點」面板,可以直接指定現有節點,或新增一個節點當總管。
  - 被指定的節點固定顯示在總管區塊中間,不論它目前是什麼狀態。
  - 總管的對話視窗標題會標示「總管」,並有「解除總管」按鈕。
  - 總管存在設定的 `chief`,重開主控台後還在;刪除總管節點時會自動解除。
- **總管守則**:被指定為總管的節點,身分設定會加上一段守則(`core.ts` 的 `chiefRules`),要求它:
  - 先用 `list_nodes` 看有哪些節點,再判斷這件事交給誰。句首叫了名字就交給那個節點。
  - 用 `ask_node` 交辦,需要討論時用 `start_meeting`。
  - 交辦前用一句話說明要交給誰、做什麼;判斷不出來就先問,不要猜。
  - 沒有明確要求時,自己不改檔案、不執行指令。
  - 回報要簡短,因為回覆會被念出來。

  守則在節點啟動時就放進身分設定;中途指定或解除時,會在下一則指令前用「主控台通知」告知。
- **全域語音**:在總管的對話視窗按住「說話」,就等於對整個主控台說話。總管是你從桌面交辦的,所以完成時 2a 會念出結果;被它分派出去的節點屬於互相呼叫,不會念。
- **分派前確認**:用總管節點的權限模式控制。「每次詢問」模式下,每次分派前都會先跳「呼叫節點」授權,這也是建議的設定;「自動」模式會直接派出去。
- **驗收**:`bash tests/chief.sh`(假資料模式,會截圖)。
- **之後可以加的**:不用打開總管視窗的全域按住說話按鈕或快捷鍵、句首叫名字時跳過總管直接交給該節點、總管在面板上的分派狀態顯示。

## 語音輸入的後續改進(原 2b,延後)

- 句首稱呼切換節點:只認句首,句子中間提到名字不切換;判斷不出來時讓你點選。
- 別名:依節點 id 存放,每個節點最多 5 個;刪除節點時一併清除;諧音錯字型的別名不放進辨識提示詞。
- 草稿保護:每個節點的輸入框各自保留;辨識失敗或辨識途中切換視窗,草稿都不會不見。
