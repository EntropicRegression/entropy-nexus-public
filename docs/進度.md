### 乾淨建置與打包步驟(可直接照做)

在主控台 repo 根目錄開 PowerShell。以 `1.1.0` 為例,換版本時改 `$v`。要打包合併後的 main 時,第 2 步把 `HEAD` 換成 merge commit。

1. 確認狀態:
   ```powershell
   $v = '1.1.0'
   git fetch; git status -sb                         # 分支和遠端一致,要打包的 commit 已推送、CI 通過
   git status --short -- tools/voice-server build package.json   # 必須沒有輸出(這些直接從主目錄打包,不能混入別人進行中的改動)
   ```
2. 建一個乾淨的 worktree(只含已提交的內容),接上主目錄的 node_modules:
   ```powershell
   git worktree add --detach "..\nexus-build-$v" HEAD
   New-Item -ItemType Junction -Path "..\nexus-build-$v\node_modules" -Target (Resolve-Path .\node_modules)
   ```
3. 在 worktree 裡只建置,不打包:
   ```powershell
   Push-Location "..\nexus-build-$v"; npx electron-vite build; Pop-Location
   ```
4. 把 worktree 的 `out/` 換進主目錄(先和 voice assistant 確認它沒有在跑 dev 或建置):
   ```powershell
   if (Test-Path .\out) { Move-Item .\out ".\release\out.before-$v" }   # 備份放在 release/ 下(已被 .gitignore 忽略)
   Copy-Item -Recurse "..\nexus-build-$v\out" .\out
   ```
5. 在主目錄打包,輸出到帶版本號的新資料夾(不要用 `npm run dist`,它會用共用工作樹重新建置 `out/`):
   ```powershell
   npx electron-builder --win nsis --config.directories.output="release/$v"
   Get-ChildItem "release\$v\Entropy-Nexus-Setup-$v.exe"   # 確認安裝檔在
   ```
   不再寫到 `release/` 根目錄或 `release/next`:根目錄的 `win-unpacked` 會被執行中的主控台佔住(EBUSY)。
6. 清理 worktree:**先解除 junction,再移除 worktree**,否則可能順著連結刪到真正的 node_modules:
   ```powershell
   cmd /c rmdir "..\nexus-build-$v\node_modules"   # 只移除連結本身
   Test-Path "..\nexus-build-$v\node_modules"     # 必須是 False
   git worktree remove "..\nexus-build-$v"
   ```
   `release/out.before-$v` 確認新版裝好、能啟動之後再刪。
7. 停機時再裝(見「下一步」第 1 點的順序)。裝好後在「關於」確認版本是 `$v`。
