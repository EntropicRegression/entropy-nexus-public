# Entropy Nexus

把 Claude Code、Codex、Antigravity 三家 CLI 的 agent 集中管理的科技風主控台。

目前進度:階段 8 完成。Claude Code、Codex、Antigravity 三家都接上真正的 CLI,直接啟動你自己安裝並登入的程式。Antigravity 在無視窗模式不會詢問權限,所以它的節點沒有授權按鈕。

## 執行

```bash
npm install
npm run dev      # 開發模式,改程式會即時更新
npm run build    # 建置到 out/
npm start        # 執行建置後的版本
npm run typecheck
npm run dist     # 打包成 Windows 安裝檔,輸出到 release/
```

安裝檔沒有程式碼簽章,第一次執行時 Windows SmartScreen 會警告,需要按「其他資訊」再「仍要執行」。圖示由 `npx electron tools/make-icon.cjs` 產生到 `build/icon.png`。

節點都要自己按「新增節點」建立。設定 `NEXUS_FAKE=1` 可以讓三家都改用假資料轉接器(開發畫面時用),此時第一次啟動會自動放入六個假資料節點。

## 結構

- `src/shared/types.ts`:狀態、事件與介面的共用型別
- `src/main/store.ts`:事件資料庫(SQLite,使用 Electron 內建的 `node:sqlite`)
- `src/main/core.ts`:核心服務,管理節點與 session;事件先寫資料庫再推送給畫面
- `src/main/procs.ts`:CLI 子行程的記錄與清理
- `src/main/changes.ts`:任務前後的工作區快照、差異計算、還原與提交
- `src/main/remote.ts`、`src/main/remote-page.html`:手機遠端的伺服器與手機版頁面
- `src/main/access.ts`:遠端裝置的權限規則(角色、節點範圍、哪些動作寫進操作紀錄)與資料過濾
- `src/main/remote-shim.js`:瀏覽器版完整介面用的橋接腳本,取代 preload,把同一組 `window.nexus` 函式改成經 HTTP 呼叫
- `src/main/hooks-observer.ts`:外部觀察的 hooks 接收端、外部觀察節點、hooks 的安裝與移除
- `src/main/terminal.ts`:終端機模式的虛擬終端機
- `src/main/worktree.ts`:獨立工作區的建立、合併、開 PR 與移除
- `src/main/sessions.ts`:列出三家 CLI 的舊 session
- `src/main/portraits.ts`:立繪資料夾與圖檔讀取
- `src/main/interop.ts`:節點互相呼叫的工具服務(本機 MCP 伺服器)
- `src/main/reveal.ts`:回覆裡的路徑解析與在檔案總管中顯示
- `src/main/media.ts`:對話圖片的存檔與受限讀取(`nexus-file://` 協定、手機的 `/api/file`)
- `src/main/adapters/adapter.ts`:轉接器介面,每家 CLI 實作一個
- `src/main/adapters/claude.ts`:Claude Code 轉接器
- `src/main/adapters/codex.ts`:Codex 轉接器(`codex app-server`);找不到 PATH 上的 codex 時會改用 Codex 桌面版內附的執行檔,也可用 `NEXUS_CODEX_BIN` 指定
- `src/main/adapters/antigravity.ts`:Antigravity 轉接器(`agy` 的 stream-json 模式);可用 `NEXUS_AGY_BIN` 指定執行檔、`NEXUS_AGY_MODEL` 指定模型;設定 `NEXUS_AGY_ACP=1` 改走 `agy acp`(見下方「ACP 轉接器」)
- `src/main/adapters/acp.ts`:通用的 ACP(Agent Client Protocol v1)轉接器,以 JSON-RPC over stdio 和支援 ACP 的 CLI 對話;執行檔、參數、顯示名稱、環境變數、模式對應與額度查詢都由 `AcpConfig` 指定
- `src/main/adapters/fake.ts`:假資料轉接器
- `src/preload/index.ts`:畫面可呼叫的固定函式
- `src/renderer/src/board.ts`:PixiJS 主面板
- `src/renderer/src/App.tsx`:HUD、節點清單、事件紀錄、新增面板
- `src/renderer/src/Tasks.tsx`:任務面板
- `src/renderer/src/Remote.tsx`:手機遠端的設定面板
- `src/renderer/src/Observe.tsx`:外部觀察的設定面板與節點清單的「外部」區塊
- `src/renderer/src/Markdown.tsx`:回覆排版
- `src/renderer/src/Terminal.tsx`:終端機畫面
- `src/renderer/src/OldSessions.tsx`:開啟舊 session
- `src/renderer/src/Fork.tsx`:分支對話的小面板(對話視窗與開啟舊 session 共用)
- `src/renderer/src/Review.tsx`:變更檢視
- `src/renderer/src/Hover.tsx`:懸浮資訊卡與血量條
- `src/renderer/src/Dialog.tsx`:對話視窗
- `src/renderer/src/Portrait.tsx`:立繪佔位圖
- `tests/`:各階段的驗收腳本。不花額度的(假資料模式或直接用 node):`walkthrough.e2e.js`、`budget.e2e.js`、`phase5-fake.e2e.js`、`worktree-setup.sh`(獨立工作區的環境初始化)、`persona-fake.sh`(角色卡,含手機端路由)、`queue-fake.sh`(指令排隊,含重開與手機端)、`review-comments.sh`(行內評論與跨節點審查)、`review-prompt.test.mjs`(行號推算與提示詞組裝)、`fork-fake.e2e.js`(分支對話;要設 `NEXUS_FAKE=1 NEXUS_FAKE_FORK_LAZY=1`,`NEXUS_TEST_CWD` 指向有提交的 git 版本庫,用同一個資料夾連續執行兩次)、`node tests/acp.test.js`(ACP 轉接器,對假的 ACP agent `acp-fake-agent.js` 跑)、`node tests/observe.run.js`(外部觀察)、`attachments.sh`(附件、貼上與手機上傳)、`media.sh`(對話圖片、讀檔協定的正反測試、手機顯示與朗讀)、`web-full.sh`(瀏覽器版完整介面)。會用到真正 CLI 的:`observe.run.js --real`、`NEXUS_ACP_REAL=1 node tests/acp.test.js`、`agy-acp.e2e.js`(`NEXUS_AGY_ACP=1` 的整合驗收)、`fork-real.e2e.js`、`claude-content.test.mjs --live`,以及其餘各階段的腳本

資料庫位置:`%APPDATA%\entropy-nexus\nexus.db`。

## 自訂立繪

立繪放在 `%APPDATA%\entropy-nexus\portraits\<角色名稱>\`,檔名是表情:`neutral`(必要)、`thinking`、`busy`、`asking`、`troubled`、`asleep`,支援 png、webp、jpg。新增節點面板的「角色」欄位可以選,旁邊的「資料夾」按鈕會開啟這個位置。沒有自訂立繪時顯示 [REDACTED] 字樣的預設圖。

Q 版頭像:在角色資料夾裡放 `avatar.png`(也接受 `chibi_avatar.png`,以及 webp、jpg),主面板上使用這個角色的節點會把頭像裁成六角形畫在節點裡(六角形會畫大一些),外框仍是後台的顏色,狀態改用右下角的小圓點表示;沒有頭像的角色與沒選角色的節點維持原本的六角形。建議用正方形、臉在中間偏上的圖。頂部的「頭像 開/關」可以切換,設定會記住;放了新圖檔後把開關關掉再打開就會重新讀取。子代理節點沿用上層節點的角色,所以也會顯示頭像。瀏覽器版完整介面同樣支援。驗收:`bash tests/avatar.sh`。

角色卡:在角色資料夾裡放 `persona.md`(也接受 `persona.txt`,兩者都有時以 .md 為準),寫下這個角色的身分、說話風格與職責,上限 8000 字。選了角色後,新增節點面板與對話視窗「設定」的角色欄位下方會出現角色卡,可以直接檢視與編輯(手機版在節點的「角色卡」按鈕)。同一個角色的節點共用一份角色卡。只有角色卡、沒有圖檔的資料夾也能選,畫面用預設圖。角色名稱不能含路徑字元,讀寫都限制在立繪資料夾裡。

## 其他行為

- 手機遠端:頂部「手機」打開後,主控台會開一個手機版的操作頁面,預設只在 Tailscale 的位址上聆聽(電腦和手機都要裝 Tailscale 並登入同一個帳號)。用手機掃 QR code 配對後,可以看節點與任務、下指令、排隊與取消排隊中的指令、允許或拒絕授權、回答提問、中斷、休眠與喚醒;也可以新增節點(可勾選獨立工作區)、開啟舊 session、改名、換模型、檢視與編輯角色卡、終止、合併工作區、檢視變更並還原或提交、附上手機裡的圖片或 PDF(圖片 8 MB、PDF 20 MB 以內,最多 6 個,送出前可個別移除)、看剩餘額度與花費、調整同時上限與額度上限。終端機模式與拖放檔案只能在電腦上用。配對碼五分鐘有效、只能用一次;已配對的裝置可以在同一個面板撤銷。也可以勾選允許同一個 Wi-Fi,但那種連線沒有加密。連接埠是 47615(可用 `NEXUS_REMOTE_PORT` 更改)。
- 遠端裝置的權限:每支配對的裝置有一個角色與節點範圍,在「手機」面板產生配對碼之前選好(面板上「下一支配對裝置的權限」,配對碼旁會顯示),之後可以在裝置清單按「權限」修改,立即生效。
  - 角色:「完整」和坐在電腦前相同;「操作」可以對節點下指令、排隊、中斷、回應授權、回答提問、休眠與喚醒,附件只能是圖片與 PDF(和手機版相同的限制);「唯讀」只能看節點狀態與對話。
  - 節點範圍:「全部節點」或「只有指定的節點」。範圍外的節點對那支裝置不存在(清單、任務、事件、即時更新、圖片都看不到);子代理跟著上層節點。之後新增的節點不會自動加進指定的範圍,節點終止時會從範圍裡移除。完整角色一律不限節點。
  - 非完整的角色不能:新增或終止節點、改名換模型、角色卡、同時上限與額度上限、「手機」面板(含讀取或產生配對碼)、外部觀察、舊 session、分支、終端機模式、還原、提交、合併、開 PR、送回修改與送交審查、瀏覽電腦的資料夾、上傳任意檔案。
  - 限制在伺服器端執行(`access.ts` 的規則表,沒列出的功能只有完整角色能用);畫面上只是把不能用的按鈕隱藏。舊版配對的裝置沒有角色資料,當成完整。每次啟動後「下一支配對裝置的權限」回到完整。
  - 注意:「操作」角色能下指令也能回應授權,實際上可以讓範圍內的 agent 在這台電腦上做事;自動模式的節點不會詢問授權,面板在選到這種節點時會警告。「限定節點」限制的是碰得到哪些 agent,不是 agent 能做什麼。
  - 非完整角色送出或排入的指令,會在節點的對話裡留一則說明,註明是哪支裝置送的。
  - 操作紀錄:會改變狀態的動作、被拒絕的嘗試、配對、撤銷與修改權限都記在資料庫(`audit` 表),包含時間、裝置、角色、動作、節點、內容摘要與是否被拒;單純讀取不記。在「手機」面板底部的「操作紀錄」檢視,可依裝置篩選或只看被拒絕的,保留 90 天。
  - 驗收:`bash tests/access.sh`(從外部用 HTTP 逐項檢查三種角色的允許與拒絕、即時更新的過濾、紀錄內容)、`bash tests/access-ui.sh`(面板設定配對權限,再以唯讀裝置連進完整介面與手機版頁面檢查畫面)。
- 瀏覽器版完整介面:手機遠端打開後,用另一台電腦的瀏覽器開啟同一個網址(`http://<Tailscale 位址>:47615/`),輸入配對碼,看到的是和桌面視窗同一份畫面程式,功能也相同(面板、對話、任務、變更檢視、舊 session、角色卡、終端機模式、外部觀察、手機面板)。網址可以用 Tailscale 的位址、這台電腦的名稱或 `*.ts.net` 的名稱。首頁依瀏覽器種類決定:手機給手機版頁面,電腦給完整介面;`/m` 一律是手機版,`/full` 一律是完整介面。和桌面視窗不同的地方只有原生視窗做不到的部分:「附加」、拖放與貼上改成把檔案上傳到主控台的暫存資料夾(單檔 50 MB 以內,七天後清掉);新增節點的「瀏覽」改成頁面內的資料夾清單,列的是主控台那台電腦的資料夾;立繪的「資料夾」按鈕只提示位置;系統通知只在主控台那台電腦上跳;Ctrl+N 這類被瀏覽器佔用的快捷鍵無效。連線中斷時頂端會提示,恢復後自動重新載入。完整介面讀的是建置後的 `out/renderer`,所以 `npm run dev` 從沒建置過時只有手機版頁面,已建置過則是上次建置的版本。驗收:`bash tests/web-full.sh`(假資料模式,會截圖和桌面畫面對照)。
- 節點互相呼叫:不同家的 agent 可以把工作交給面板上的其他節點。主控台開一個只聽 `127.0.0.1` 的 MCP 工具服務(連接埠 47617,可用 `NEXUS_INTEROP_PORT` 更改),啟動每個節點的 CLI 時掛上去,agent 就多了三個工具:`list_nodes`(列出其他節點與狀態)、`ask_node`(把指令交給另一個節點,等它這個回合結束後取回答覆)、`wait_reply`(對方跑比較久時 `ask_node` 會在 45 秒後先返回一個 request_id,用它接著等)。規則:只能呼叫面板上已有、沒有在執行的最上層節點(待命,或上一個回合出錯停下來的),不能呼叫自己、子代理、休眠或終端機模式的節點,也不能自己開新節點;對方正在(直接或間接)等自己的答覆時不能反過來呼叫它,呼叫鏈最多三層;對方忙碌時直接回報忙碌,不排隊。要不要經過你同意跟著**呼叫方**節點的權限模式:「自動」直接送出;「每次詢問」會先在呼叫方節點上跳授權,顯示要交給誰與指令全文,拒絕時工具回報被拒。被呼叫的節點照它自己的權限模式、同時上限與額度上限執行,送給它的指令前面會加一行「(主控台:這則指令來自節點「某某」(後台 · 模型),不是使用者直接下的;你這個回合的答覆會交還給它。)」,所以被呼叫的 agent 自己也知道是誰找它、答覆會交給誰(呼叫方則從 `list_nodes` 與答覆的開頭知道對方的名字);也照常產生一筆任務;它的回合出錯、被中斷或被終止時,原因會回報給呼叫方。每個節點有自己的網址(路徑帶一組亂數權杖,每次啟動主控台都換新),服務由權杖得知是誰在呼叫。三家的掛法都只對主控台啟動的那個行程生效,不動你的全域設定:Claude Code 用 `--mcp-config` 加 `--allowedTools`;Codex 用 `thread/start`(以及續接、分支)的 `config.mcp_servers`,並設 `default_tools_approval_mode: approve`;Antigravity 不能用參數直接掛,改在主控台資料夾 `interop/agy/<節點>/` 產生一個工作區外掛(`.agents/plugins.json` 與外掛的 `mcp_config.json`),用 `--add-dir` 加進工作區,再用 `--settings` 放行 `mcp(nexus_tools/*)`,並在這個 session 的第一則訊息前面提示伺服器名稱(agy 的 MCP 工具是延遲載入的,模型要知道名稱才找得到)。以 `NEXUS_AGY_ACP=1` 走 ACP 的 Antigravity 節點目前沒有掛這組工具。設定 `NEXUS_INTEROP=0` 可以關掉整個功能;已經在執行的節點要重新啟動(休眠再喚醒)才會掛上。程式在 `src/main/interop.ts`。驗收:`bash tests/interop.sh`(假資料模式,另一支腳本扮演各節點的 CLI)、`bash tests/interop-real.sh <呼叫方後台> <被呼叫方後台> [模型] [模型]`(真正的 CLI,會用到一點額度)。
- 會議(多輪討論):節點互相呼叫的工具服務另外提供 `start_meeting`,讓一個節點召開會議、其他節點輪流發言。召開者是主持人;參與者是面板上其他 1 到 5 個節點,規則和 `ask_node` 相同(不能找自己、子代理、休眠或終端機模式的節點,也不能找正在等自己的節點)。主控台每一輪依序請參與者發言,每人一個回合:送給它的指令開頭註明這是誰召開的會議、有哪些參與者、現在第幾輪,第一次附上主題,之後只附「自己上次發言之後其他人的新發言」(各節點自己的 session 記得先前的內容)。輪數上限 1 到 6,預設 2。主持人發言(`host_turns`,預設開啟):每一輪結束、還有下一輪時,`start_meeting`/`wait_reply` 會回傳「輪到你(主持人)發言」與它上次發言之後的新發言,主持人用 `meeting_say` 工具(參數 `request_id`、`text`、`end`)發言,發言會記成「主持人」的一則並轉給下一輪的所有參與者,接著進行下一輪;`end: true` 則結束會議(可同時附結語)。同一輪所有參與者都寫「【無補充】」時也先交給主持人決定;主持人超過 15 分鐘沒有回應就散會。最後一輪結束後不再輪到主持人,直接交回紀錄。`host_turns: false` 時主持人不發言,同一輪所有人都在發言最後寫「【無補充】」就提前結束,否則跑到輪數上限。結束後把完整的會議紀錄交還給召開者,由它整理結論回報。會議通常要幾分鐘,`start_meeting` 等 45 秒還沒開完就先回傳 request_id,用 `wait_reply` 接著等。授權:召開者是「每次詢問」模式時,開會前在召開者節點上跳一次「召開會議」授權(列出參與者、輪數與主題全文),允許後整場放行;「自動」模式不問。每則發言即時記在召開者的對話裡(「【會議 <id>|第 N 輪|名稱】」),你看得到全程;中斷召開者、或它的回合因故結束,就會散會,正在發言的節點也一併中斷。參與者輪到時正在忙或已經不在,該輪略過並記一則說明;單次發言超過 15 分鐘會被中斷並換下一位。每位參與者照自己的權限模式與額度上限執行,每次發言都算它的一個回合(也各產生一筆任務)。驗收:`bash tests/meeting.sh`(假資料模式)、`bash tests/meeting-real.sh <主持人後台[:模型]> <參與者後台[:模型]> …`(真正的 CLI,會用到一點額度)。
- 外部觀察(hooks 附掛模式):在主控台以外(VS Code 或 Windows Terminal)執行的 Claude Code,可以即時顯示在右側節點清單的「外部」區塊,狀態有規劃中、執行中(附工具名稱)、待授權、待命、異常,游標停在列上可看資料夾、session id 與最近幾筆事件。頂部「外部觀察」打開設定面板,按「安裝 hooks」才會修改 Claude Code 的使用者設定檔(`~/.claude/settings.json`),啟動時絕不自動修改。安裝時先備份(同資料夾的 `settings.json.entropy-nexus-<時間>.bak`),只為 UserPromptSubmit、PreToolUse、PostToolUse、PermissionRequest、Notification、Stop、StopFailure、SessionEnd 各加一個指向 `http://127.0.0.1:<連接埠>/entropy-nexus-hook/<權杖>` 的 http 型 hook,原有的 hooks 與其他設定不動;重複安裝不會重複新增;設定檔不是合法 JSON 時中止,不覆寫。「移除 hooks」只拿掉網址帶 `/entropy-nexus-hook/` 的項目。SessionStart 依官方文件不支援 http 型 hook,所以外部 session 要等第一個事件(通常是送出指令)才出現;已經在執行的 Claude Code 要重開才會讀到新的 hooks。接收端只聽 127.0.0.1、權杖不對一律拒絕、body 上限 256 KB,收到就回 200 空內容,不做允許或拒絕的決定(純觀察);主控台沒開時連線立刻失敗,Claude Code 照常執行(官方文件:http hook 失敗與逾時都不會阻擋)。主控台自己啟動的 CLI 會帶 `NEXUS_HOOK_MANAGED=1` 環境變數,hook 以標頭帶回,接收端就略過,另外也用 session id 排除面板上已有的節點。外部節點 10 分鐘沒有事件標成待命、1 小時沒有事件移除。外部節點進入待授權時響提示音、視窗不在前景時跳系統通知,但不提供授權按鈕,要到那個終端機處理。每列的「接手」會走「開啟舊 session」建立正式節點;第一次按會先警告外部的 Claude Code 可能還在執行,請先在那邊 /exit,再按「確定接手」。權杖存在主控台設定裡,「換新權杖」後要重新安裝 hooks。連接埠是 47616(可用 `NEXUS_HOOKS_PORT` 更改,被佔用時面板會顯示錯誤)。Codex 的 hooks 只有 command 型,Windows 上的支援也不穩定,目前只支援 Claude Code。
- 身分設定:每個節點啟動時會被告知自己在主控台裡的名字(Claude Code 用附加的系統提示,Codex 用 developer instructions,Antigravity 沒有這類參數,改在新對話的第一則訊息前面帶上)。節點選了有角色卡的角色時,角色卡會包在「主控台給的角色設定」區塊裡接在名字後面,並註明這不是使用者的指令。改名、換角色或角色卡被編輯後,下一則指令前會帶上「主控台通知」告訴 agent 新的名字或角色設定(使用同一張角色卡的節點都會收到);對話紀錄裡仍只留使用者原本的文字。文字由 `core.ts` 的 `persona()` 組出;Claude Code 的設定走命令列參數(由 Node 直接啟動 exe,不經 shell,換行與引號不會被改寫),Codex 與 Antigravity 走 JSON。測試時設 `NEXUS_FAKE_ECHO=1`,假資料轉接器會把收到的身分設定與實際送出的文字記成 note。終端機模式和接回來的 Antigravity 舊對話不會帶這段設定。
- 快捷鍵:Alt+N 跳到下一個需要你的節點,Alt+A / Alt+S / Alt+D 允許、本次都允許、拒絕,Alt+I 中斷,Alt+Enter 把輸入的指令排進佇列,Esc 或 Alt+W 關閉對話視窗,Alt+F 把對話視窗展開到滿或還原,Alt+E 展開或收回輸入框,Ctrl+N 新增節點,Ctrl+O 開啟舊 session,F1 顯示完整清單。
- 對話視窗展開:識別列的「▲ 展開」(或 Alt+F)讓對話視窗向上佔滿整個面板,再按一次還原成下半部;這個設定會記住,換節點或重開後維持。輸入框右邊的「展開」(或 Alt+E)把輸入框變成多行編輯區(視窗展開時更高),這時 Enter 是換行、Ctrl+Enter 才送出,Alt+Enter 仍是排隊;送出或排隊後自動收回。驗收:`bash tests/dialog-expand.sh`。
- Antigravity 的自動更新:agy 每次啟動時,若距離上次檢查超過 15 分鐘就會另開一個看得見的主控台視窗檢查更新(實測 agy 1.5.10)。主控台每個回合結束都會啟動一次 agy 查額度,所以會常常跳視窗;因此主控台啟動 agy 時一律帶 `AGY_CLI_DISABLE_AUTO_UPDATE=true` 關掉自動更新。要更新 agy 請自己在終端機執行 `agy update`;終端機模式不帶這個設定,在那裡 agy 仍會自動更新。
- 附加檔案與圖片:把檔案拖進對話視窗、按「附加」,或在輸入框直接貼上截圖(存到資料資料夾的 `attachments/`,只收 PNG、JPEG、GIF、WebP,10 MB 以內,七天後自動清掉)。送出前會顯示縮圖(其他檔案顯示副檔名),可以個別移除,標籤上標示「內嵌」或「僅路徑」。附件的路徑一律寫進指令;後台能直接看的類型另外內嵌給模型:Claude Code 收圖片與 PDF(圖片約 3.75 MB、PDF 10 MB、一則合計 20 MB 以內),Codex 收圖片,Antigravity 只收路徑(以 `NEXUS_AGY_ACP=1` 改走 ACP 時可收圖片),由它自己用讀檔工具查看,圖片它看得到內容。agy 的無視窗模式會自動拒絕讀取工作區以外的檔案,所以啟動時會把主控台的附件資料夾(`attachments/` 與 `uploads/`)用 `--add-dir` 加進工作區;工作目錄以外的附件(例如從桌面拖進來的檔案,50 MB 以內)送出前會複製一份到 `attachments/`,交給 agy 的是複製後的路徑,對話紀錄裡仍是原本的文字。驗收:`bash tests/agy-attach.sh`(真正的 agy,會用到一點額度)。不能內嵌的附件(其他類型、太大或讀不到)會在對話裡用一行說明告訴你,模型需要時自己用工具去讀。類型依副檔名判斷(`shared/types.ts` 的 `attachmentKind`)。
- 回覆排版:程式碼區塊有等寬字與複製鈕,支援標題、清單、粗體與行內程式碼。也會顯示圖片:`![說明](路徑)` 語法(路徑有空白時寫成 `![說明](<路徑>)`),以及單獨成行或寫在行內程式碼裡、副檔名是 png、jpg、gif、webp、bmp 的本機路徑(相對路徑以節點的工作目錄為準),會在該段下方附上預覽。圖片有最大尺寸,點一下放大,Esc 或再點一下關閉。本機圖片經 `nexus-file://` 協定讀取,只開放節點工作目錄裡、以及主控台媒體資料夾裡的圖片(解開符號連結與 junction 後再檢查一次,單檔上限 20 MB,不支援 SVG),其他位置一律讀不到,這時 `![]()` 會退回顯示路徑文字。遠端 http(s) 圖片不會自動載入,只顯示「載入圖片」按鈕,按了才連線。
- 路徑連結:回覆裡以行內程式碼寫出的檔案或資料夾路徑(例如 `src/main/core.ts`、`src/main/core.ts:120`、`Desktop\某個資料夾`),以及 Markdown 連結的目標(Antigravity 習慣寫成 `[檔名](file:///路徑)`,含百分比編碼與 `#L12` 片段),實際存在時會變成連結,點一下在檔案總管中顯示:資料夾直接打開,檔案則打開所在的資料夾並選取,不會執行或用預設程式開啟檔案。相對路徑依序以節點的工作目錄、往上四層(agent 常從版本庫根目錄寫路徑)、使用者的家目錄為基準,第一個存在的才算;沒有分隔符號的單一檔名只在工作目錄裡找,而且要有副檔名。網址與網路路徑(`\\server\share`)不處理。檔案後來被移走時,點了會改成刪除線。瀏覽器版完整介面沒有這個功能(檔案總管在主控台那台電腦上)。驗收:`bash tests/reveal.sh`。
- 工具結果的圖片:Claude Code 工具結果裡的圖片(例如 Read 讀圖、MCP 截圖)、Codex 的看圖(imageView)、生成圖片(imageGeneration)與 MCP 工具回傳的圖片,會存成檔案並在對話裡顯示,事件紀錄只記路徑。檔案放在 `%APPDATA%\entropy-nexus\media\<節點 id>\`,單張上限 10 MB,每個節點最多保留 60 張、合計 100 MB,超過時從最舊的刪起;終止節點時,沒有 session 可接回的節點一併刪除,可以從「開啟舊 session」接回的保留,30 天沒有新圖片的資料夾在啟動時清掉。手機版也看得到這些圖片(經 `/api/file`,同樣的路徑限制,要已配對的裝置)。
- 節點設定:對話視窗的「設定」可以改名稱、角色與模型;換模型會重新啟動 session,對話內容保留。工作目錄不能更換。
- 終端機模式:對話視窗的「終端機」會停下結構化 session,改在視窗內的虛擬終端機執行原生 CLI 並接回同一個對話;按「回到對話」切回來。這個模式下主控台不解析內容,所以沒有狀態、授權按鈕與變更檢視。
- 回答提問:agent 用提問工具問你時,對話視窗會顯示題目與選項,可以點選、自行輸入或略過。
- 即時串流:回覆邊生成邊顯示。
- 同資料夾警告:新增節點時,該資料夾已有節點會提醒;勾選獨立工作區就不會互相影響。
- 獨立工作區:新增節點時勾選「獨立工作區」,節點會在自己的 git worktree 與分支(`nexus/名稱-編號`)上工作,不會和其他節點互相覆寫。工作區放在 `%APPDATA%\\entropy-nexus\\worktrees\\`。對話視窗可以把成果「合併回」原本的分支(有衝突會自動取消),或推送分支並用 GitHub CLI「開 PR」。終止節點時,工作區乾淨且已合併才會自動移除,否則保留。worktree 只隔離檔案,不是沙箱。建立工作區後會自動初始化環境,結果顯示在節點對話裡(電腦與手機新增都一樣):原版本庫根目錄有 `.worktreeinclude`(gitignore 風格,一行一個樣式,`#` 為註解)時,把符合的未追蹤檔案複製到工作區的相同位置;沒有時預設複製 `.env`、`.env.*` 這類環境檔(不進 `node_modules`、`.git` 與 `dist` 之類的大資料夾)。原版本庫根目錄與兩層內子專案的 `node_modules` 會用 junction(非 Windows 為 symlink)連結回原版本庫,不必重裝;移除工作區前會先解除這些連結,不會刪到原專案的 `node_modules`。沒被 `.gitignore` 忽略的連結與複製檔會寫進版本庫的 `.git/info/exclude`(與原版本庫共用,所以原版本庫的 `git status` 也不會再列出它們),避免被當成修改或在合併時被提交。初始化失敗不影響建立節點;不會自動執行任何安裝或 setup 指令,需要的話請自己在節點裡執行。
- 還原與提交:變更檢視可以還原單一檔案或整個任務(任務之後又被改過的檔案會跳過),也可以把任務的修改提交成一筆 commit。還原只動工作區的檔案。
- 花費與額度上限:任務面板顯示每個任務用了多少 token(Claude 另有估算金額),懸浮資訊卡顯示節點累計。頂部「額度上限」設成例如 80,某家後台的額度用到 80% 就不再送出新指令;0 表示不限制。Antigravity 不提供額度,所以這個上限對它無效。
- 開啟舊 session:右下角「開啟舊 session」會列出主控台終止過的節點,以及 Claude Code、Codex、Antigravity 留在這台電腦上的舊對話,可依後台篩選或搜尋。主控台開過的 session 會記住當時的名稱、角色與模型,開啟時直接沿用並接回對話紀錄;第一次開啟的 CLI 對話會建立新節點,你填的名稱從此跟著這個 session 保存。清單只讀取 CLI 自己的對話紀錄(標題、資料夾、時間),不碰登入憑證。
- 分支對話:對話視窗識別列的「分支對話」,或「開啟舊 session」每列的「分支」,會從那段對話分支出一個新節點。新節點有自己的 session,之後兩邊各自發展,原本的節點與舊 session 都不受影響(不佔用)。小面板可填新名稱(預設「原名-分支」)、模型,並勾選是否用獨立工作區;同資料夾又不隔離時會出現和新增節點一樣的警告。來源是主控台的節點(包括終止過的)時,分支當下為止的對話紀錄會複製到新節點,並加一則「從節點 X 的對話分支」的說明;只存在於 CLI 紀錄裡的舊對話只加說明。來源節點還在執行時也能分支,但分支點是 CLI 當時已寫入紀錄的對話,進行中的回合可能不完整,說明裡會註明。Claude Code 用 `--resume <來源> --fork-session`,Codex 用 app-server 的 `thread/fork`;Antigravity(`agy` 1.5.10)沒有分支功能,按鈕停用。還沒有 session(沒對話過)的節點也不能分支。Claude Code 要等第一句指令才會建立分支的 session,在那之前休眠、喚醒或重開主控台,都會再從來源分支一次;拿到新的 session id 後,休眠、喚醒、換模型都用新的 id 續接。分支來源存在設定的 `fork:<節點 id>`。
- 變更檢視:任務面板上每筆任務會顯示改了幾個檔案、增減幾行,點一下可看每個檔案的前後對照;任務還在執行時也能看到目前為止的變更。對話視窗識別列的「變更」按鈕會開啟該節點最近一個任務的變更。工作目錄是 git 版本庫時,主控台在任務前後各拍一張工作區快照再相減,所以不論哪一家 CLI、用工具還是用指令改的都看得到,也不會動到你的暫存區、分支或提交;不是 git 版本庫時只能列出編輯工具回報的修改。
- 行內評論與送回修改:變更檢視的差異左側有新舊兩欄行號,點一下某一行可以留評論(新增與上下文行用新檔行號,刪除行用舊檔行號並標明是被刪除的行),評論顯示在該行下方,可編輯、刪除;「新增整體意見」可留不綁定特定行的意見。底部顯示評論數,按「送回此節點修改」會把所有評論整理成一則指令(檔案路徑、行號、該行與前後幾行程式碼、評論內容)送給產生這個任務的節點,送出後清空。節點已不存在、休眠、在終端機模式或任務還在執行時按鈕停用並說明原因。
- 跨節點審查:變更檢視底部的「送交其他節點審查」下拉選單列出其他可用的節點(排除自己、子代理、休眠、異常與終端機模式;忙碌的會標示),選一個就由主控台組合審查提示詞送出:原任務指令、由哪個節點(後台與模型)完成、變更摘要與完整 diff,並要求對方以審查者角度指出錯誤、風險與改進建議,不要修改檔案;兩個節點的工作目錄不同時會說明變更所在的路徑。diff 總長上限約 6 萬字元,超過時較大的檔案會被截斷或省略並在提示詞裡列出,二進位檔只列檔名。送出後原節點與審查節點的對話各留一則說明。
- 剩餘用量:游標停在面板的節點(或節點清單的一列)上,會跳出資訊卡,以血量條顯示該後台帳號各額度視窗的剩餘比例與重置時間,另有一條顯示這個節點的記憶空間(context)剩餘。Claude 的額度用 `claude -p /usage` 查詢(本機指令,不啟動回合、不花額度、不留下 session),節點啟動時與每個回合結束後各查一次,回合中也會即時更新;某個模型專屬的每週額度(例如 Fable)只顯示在使用該模型的節點上;Codex 啟動時就會查詢; Antigravity 的額度用 `agy -p /usage` 查詢(唯讀指令,不啟動回合、不花額度),在節點啟動時和每個回合結束後更新;它的額度依模型分組(Gemini、Claude 與 GPT、Argon),資訊卡只顯示節點模型所屬的那一組,額度上限也只看那一組。
- 任務面板:右側欄下半部。每對節點送出一句指令就自動多一筆任務,顯示內容、狀態(執行中、待授權、完成、失敗、已中斷)、由哪個節點執行與經過時間;期間呼叫的子代理、以及 Codex 回報的計畫步驟會一併列出。任務會存進資料庫,重開後還在。
- 指定模型:新增節點面板的「模型」欄位可從清單選或自行輸入;留空使用 CLI 的預設。Codex 與 Antigravity 的清單是啟動時向 CLI 查詢的,Claude 提供 opus、sonnet、haiku 三個別名。
- 子代理節點:節點呼叫子代理時,面板會自動多一個較小的子節點,只能觀看,結束約 20 秒後自動移除。Claude 與 Codex 看得到子代理裡的過程,Antigravity 只看得到開始與結束。Claude Code 在背景執行的子代理(Agent 工具預設就是背景執行)一啟動就會回報工具完成,回合也可能先結束,但子節點會留在面板上顯示「背景執行中」與最新進度,等 CLI 通知完成(`task_notification`)才結束並移除;主節點的行程結束時,還在跑的子節點一併結束。驗收:`bash tests/bg-subagent.sh`(用假的 CLI `tests/claude-fake-cli.js` 照劇本輸出事件;`NEXUS_CLAUDE_BIN` 指向 .js 檔時轉接器會用內建的 Node 執行它)。
- 同時執行上限:頂部可調整(預設 4),超過時新的指令自動排進該節點的佇列並附上說明,有節點停下來空出名額時,依排入時間先後自動送出。
- 指令排隊:節點執行中時,輸入下一句按「排隊」(或 Alt+Enter)排進佇列;回合正常完成回到待命時自動送出第一筆,每筆各成一個任務。執行中直接按 Enter 仍是回合中插話。排隊中的指令列在輸入區上方與任務面板,可編輯、取消;手機版也能排隊與取消。回合出錯、被中斷或失聯時佇列暫停(內容保留),手動送出下一句或按「繼續」後恢復;佇列送出時若被額度上限擋下,那筆留在佇列並暫停。佇列存在資料庫,重開後還在;休眠中的節點不會送出,喚醒並待命後才繼續。終止節點時佇列一併丟棄。每個節點最多排 50 筆。
- 失聯偵測:CLI 行程結束,或執行中超過 10 分鐘沒有任何事件,節點會移到異常區塊,可按「重新連線」。
- 提示音與系統通知:節點進入待授權或異常時響一聲;視窗不在前景時另外跳系統通知。提示音可在頂部關閉。
- 語音播報(朗讀):頂部「朗讀」打開後(預設關閉,設定會記住),你從桌面交辦的回合正常完成時,會用系統語音念一句重點(規則摘要:略過程式碼、表格、網址與路徑,優先念要你決定的事、還沒解決的問題、已完成的成果,最多約 65 個朗讀單位);節點等你授權、有問題要問你,或你交辦的回合出錯、失聯、排隊的指令被額度上限擋住時,也會提醒。節點互相呼叫、會議、遠端送來的指令與被中斷的回合不念完成摘要;授權與提問不分來源都會提醒。多則通知依序排隊播放:授權與提問優先、完成通知最多 5 則且超過 60 秒就略過、同一節點只留最新一則、故障提醒有頻率限制;按住「說話」錄音時暫停播報。有中文時優先用台灣中文語音。朗讀中頂部會出現「停止朗讀」(停掉目前這則並清空佇列),關掉朗讀也會立刻停止。子代理的回覆不念。規格見 [語音模式規劃](語音模式規劃.md) 的 Phase 2a;驗收:`node tests/voice-summary.test.mjs`、`bash tests/voice-speech.sh`。
- 語音模式(實驗性,Phase 1:語音輸入):頂部「語音」打開設定面板(預設關閉,設定會記住)。啟用後,主控台會用設定的啟動指令(留白時是 `python "<專案>/tools/voice-server/server.py"`)啟動本機的語音服務(faster-whisper,預設模型 large-v3-turbo)。狀態依序是啟動中、模型載入中、可以使用,失敗時顯示原因與服務的輸出。可以使用之後,對話視窗的輸入框旁會出現「說話」按鈕:按住說話、放開後轉成文字接在輸入框的內容後面,不會自動送出,最長 60 秒;節點名稱會當成提示詞,幫助辨識。語音只在本機處理,不能用語音回覆授權。安全:服務只聽 `127.0.0.1`,每次啟動換一個空的連接埠與一組亂數權杖(以環境變數交給服務),請求要帶權杖並檢查 Host;這組功能只註冊給桌面畫面,不在遠端的方法表裡,手機與瀏覽器版都呼叫不到(瀏覽器版不顯示按鈕)。主控台正常結束時用 `taskkill /T` 結束整個服務行程樹;被強制關閉時,服務偵測到主控台不在了,會在幾秒內自己結束。另外,主控台現在只允許主視窗取用麥克風(只限音訊),攝影機與其他瀏覽器權限一律拒絕(複製到剪貼簿與全螢幕照常)。環境準備見 `tools/voice-server/README.md`。程式在 `src/main/voice.ts`、`src/renderer/src/Voice.tsx`、`tools/voice-server/server.py`。驗收:`bash tests/voice.sh`(需要 Python 與 faster-whisper,不花 CLI 額度)。
- 節點自己的聲音(語音模式 Phase 3,選用):在「語音」設定面板填入 CosyVoice 的資料夾後,語音服務會同時載入 CosyVoice 2(Apache-2.0)。語音播報會改用角色的聲音:角色資料夾裡的 `voice.wav` 是參考錄音,`voice.txt` 是錄音的內容(選用,沒有就自動辨識),`style.txt` 是語氣指令(選用)。沒有 `voice.wav` 的角色,或合成失敗、超過 15 秒時,改用系統語音。面板會列出各角色有沒有聲音,並可以試聽。聲音也可以直接在角色卡底下的「聲音」區塊設定(新增節點面板與對話視窗的「設定」裡都有):用麥克風錄一段(最長 15 秒)或選一個 WAV 檔、播放原音、自動辨識錄音內容後再修正、填寫語氣、試聽、移除;錄音必須是 16-bit WAV,長度 2 到 30 秒。檔案的讀寫都在主行程進行,選檔用主行程的對話框。驗收:`tests/voice-profile.e2e.js`(假資料模式)。一句播報約 3 到 5 秒合成完;和語音辨識一起常駐時,顯示卡記憶體多用約 4.6 GB(RTX 4060 Ti 實測)。只限桌面畫面,遠端呼叫不到。安裝見 `tools/voice-server/README.md`;驗收:`bash tests/voice-tts.sh`。
- 總管節點(主控語音模式):面板「執行」那一列最右側的綠色「總管」區塊。沒有總管時點區塊裡的「+」六角形,可以直接指定現有節點,或新增一個節點當總管;被指定的節點固定顯示在這個區塊。總管的身分設定會加上總管守則:收到你交代的事時,先用 `list_nodes` 看有哪些節點,再用 `ask_node`(或 `start_meeting`)交給合適的節點,交辦前先說明要交給誰,判斷不出來就先問你,沒有明確要求時不自己改檔案,回報保持簡短。在總管的對話視窗用語音說話,就等於對整個主控台說話。分派前要不要確認,跟著總管的權限模式:「每次詢問」會在每次分派前先跳授權(建議),「自動」直接派出去。對話視窗的「解除總管」可以取消;刪除總管節點時會自動解除。設定存在 `chief`,重開後仍在。驗收:`bash tests/chief.sh`。
- 行程清理:結束時會停掉所有 CLI 子行程;若主控台被強制關閉,下次啟動會清掉還留著的子行程。

## ACP 轉接器(實驗中)

`agy acp` 是 Antigravity CLI 內建的 ACP 伺服器。設定 `NEXUS_AGY_ACP=1` 後,Antigravity 節點改走這條通道,預設仍是 stream-json。和 stream-json 的差別:

- 會詢問權限:「每次詢問」用 agy 的 `default` 模式,工作目錄內的檔案修改直接執行,執行指令等動作會跳出授權按鈕(允許與拒絕);「自動」用 agy 的 `auto` 模式,它判斷不可逆的動作仍會詢問。agy 只提供「允許一次」與「拒絕」,所以沒有「本次都允許」。
- 中斷用 `session/cancel`,不必結束行程;續接用 `session/resume`(不重播對話),agent 只支援 `session/load` 時會略過重播的舊內容。
- 圖片以 base64 內嵌交給模型,不再只有路徑。
- 子代理仍只看得到啟動(agy 的 `invoke_subagent` 立刻回報完成,子代理在背景跑),子節點留到回合結束。
- 額度仍用 `agy -p /usage` 查詢;每回合的 token 數取自 `session/prompt` 的回覆,記憶空間取自 `usage_update`。
- ACP 建立的對話 id 就是 agy 的 conversation id,所以「開啟舊 session」與終端機模式(`--conversation`)都看得到。

已實測(agy 1.5.10):新對話、續接(resume 與 load)、權限允許與拒絕、串流中與等待授權時中斷、圖片輸入、模型切換(`session/set_model`)、auto 模式、用量與額度查詢、主控台結束後沒有殘留行程。尚未驗證:用 ACP 續接 stream-json 建立的舊對話、身分設定以外的系統提示(agy 有 `_meta.antigravity.systemPrompt` 但格式未公開,目前仍把身分設定帶在第一則訊息前面)、agy 的計畫(`plan`)與思考片段(實測時沒有出現)。

通用的 `AcpAdapter` 只宣告最保守的 client 能力(不提供 `fs` 與 `terminal`),agent 用自己的工具讀寫檔案與執行指令。Windows 上 `.cmd`/`.bat` 墊片經由 cmd 啟動,`.ps1` 經由 PowerShell 啟動。主控台的 `permissionMode: 'auto'` 在 agent 沒有對應模式時,會由主控台直接允許所有授權請求。

## 自我檢查用的環境變數

- `NEXUS_DATA_DIR`:把資料放到指定資料夾,不影響正式資料
- `NEXUS_AGY_ACP=1`:Antigravity 節點改走 `agy acp`(ACP 通道)
- `NEXUS_INTEROP=0`:關掉節點互相呼叫;`NEXUS_INTEROP_PORT`、`NEXUS_INTEROP_WAIT_MS`:工具服務的連接埠、`ask_node` 先返回前最多等多久(毫秒)
- `NEXUS_FAKE_NO_ERRORS=1`:假資料節點不模擬隨機失敗(預設每一步有 6% 機率「被限速」)
- `NEXUS_STALL_MS`:失聯偵測的等待時間(毫秒),測試時用來縮短
- `NEXUS_NO_SEED=1`:不要自動放入假資料節點
- `NEXUS_FAKE_SNAPSHOT=1`:假資料節點也在任務前後拍工作區快照,讓假資料模式也能測試變更檢視(預設關閉)
- `NEXUS_FAKE_FORK_LAZY=1`:假資料模式下,分支的節點要等第一句指令才回報 session(模擬 Claude Code)
- `NEXUS_SHOT`、`NEXUS_SHOT_DELAY`:等待指定毫秒後把視窗存成 PNG 並結束
- `NEXUS_TEST_SCRIPT`、`NEXUS_TEST_DIR`:在畫面裡執行指定的腳本檔;腳本把 `document.title` 設成 `SHOT:名稱` 會截圖到該資料夾,設成 `QUIT` 會結束程式
- `NEXUS_CLAUDE_SETTINGS`:外部觀察安裝與移除 hooks 時改寫這個檔案,而不是 `~/.claude/settings.json`(測試一律要設)
- `NEXUS_HOOKS_PORT`:外部觀察接收端的連接埠
- `NEXUS_OBSERVE_IDLE_MS`、`NEXUS_OBSERVE_DROP_MS`:外部節點標成待命、移除的等待時間(毫秒),測試時用來縮短
