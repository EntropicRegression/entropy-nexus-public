# 節點 session 存點(規劃)

2026-11-23 使用者提出:終止節點後想接回時,各家工具可能已經把對話清掉(Claude Code 預設 30 天自動刪除),希望主控台能把 session 永久封存一份,並在寶庫(記憶庫管理 App)顯示這些「存點」。

## 使用者裁示(2026-11-23)

| 項目 | 裁示 |
|---|---|
| 建立時機 | **終止節點時自動建立**(第一版只做這個;手動按鈕、快過期前自動備份之後再說) |
| 還原方式 | **先問再還原**:接回時發現原本的 session 檔不見了,跳出「要從存點還原嗎」,同意後放回原位再續接 |
| 涵蓋後台 | **三家都做**:Claude Code、Codex、Antigravity(Antigravity 的還原標為實驗性) |
| 寶庫顯示 | **列表加可還原狀態**:節點的封存頁列出每個存點與能不能還原,可以從寶庫要求主控台還原(走既有的喚醒網址) |

## 背景:三家的 session 檔

| 後台 | 一段對話的檔案 | 自動清除 |
|---|---|---|
| Claude Code | `~/.claude/projects/<專案>/<sessionId>.jsonl`,加上同名資料夾 `<sessionId>/`(子代理紀錄等) | 預設 30 天(`cleanupPeriodDays`,最小 1,不能設 0) |
| Codex | `~/.codex/sessions/<年>/<月>/<日>/rollout-<時間>-<sessionId>.jsonl`;封存過的在 `~/.codex/archived_sessions/` | 沒有找到自動清除 |
| Antigravity | `~/.gemini/antigravity-cli/conversations/<id>.db`(可能有 `-wal`、`-shm`)與 `brain/<id>/` | 沒有找到官方的保存期限說明 |

主控台只記 sessionId,對話本身由各家工具保存;工具清掉檔案後,即使節點還在「已終止」清單裡也接不回(`canResume` 只檢查 sessionId 與工作目錄,不檢查檔案還在不在)。

## 設計

### 1. 存放位置

```
memory-vault/
  nodes/封存/
    <名稱>-<日期>.md            ← 既有的封存檔,檔頭多一個「存點」欄位
    _存點/<節點ID>/<YYYYMMDD-HHmmss>/   ← 本機時間;同一秒撞名時加 -2、-3
      存點.json                  ← 說明檔(見下)
      files/...                  ← 依原本的相對位置複製的 session 檔
```

- 放在底線開頭的資料夾:記憶庫索引不收、`memory_read` 也拒絕讀(既有規則,`memory-tools.ts:288`),節點查不到這些原始對話。
- 同一個節點可以有多個存點(接回後又終止,會再建一個),不覆蓋舊的。

### 2. `存點.json`

```json
{
  "版本": 1,
  "節點ID": "…", "節點": "名稱", "後台": "Claude Code", "後台ID": "claude",
  "sessionId": "…", "工作目錄": "原本的工作目錄",
  "建立時間": "2026-11-23T20:00:00+08:00", "原因": "終止",
  "檔案": [{ "位置": "projects/<專案>/<id>.jsonl", "根目錄": "claude", "大小": 123, "sha256": "…" }],
  "總大小": 123
}
```

- `根目錄` 是 `claude`(`~/.claude`)、`codex`(`~/.codex`)、`agy`(`~/.gemini/antigravity-cli`)之一;`位置` 是相對那個根目錄的路徑,還原時依此放回,不存絕對路徑。
- `sha256` 用來在還原前檢查存點沒有損壞。

### 3. 建立時機與流程(主控台)

在 `removeAgent` 停掉 session 之後、標記已終止之前(檔案已經寫完):

1. 依後台找出這個 sessionId 的檔案(Claude:`projects/*/<id>.jsonl` 與 `<id>/`;Codex:`sessions/**` 與 `archived_sessions/**` 裡檔名結尾是 `<id>.jsonl` 的;Antigravity:`conversations/<id>.db*` 與 `brain/<id>/`)。
2. 複製到暫存資料夾,算好 sha256 寫 `存點.json`,最後整個資料夾改名到 `_存點/<節點ID>/<時間>/`(寫到一半失敗不會留下不完整的存點)。
3. 封存檔(有寫的話)檔頭加 `存點: nodes/封存/_存點/<節點ID>/<時間>`(和統計檔一樣,一律相對記憶庫根目錄)。
4. **失敗不擋刪除**:找不到檔案、複製失敗都只在刪除結果的說明裡寫原因,和既有的歸檔一樣。
5. 沒有 sessionId 的節點、子代理不建存點。假資料節點不建。

### 4. 還原流程(主控台)

接回(「開啟舊 session」或喚醒網址)時:

1. 先檢查原本的 session 檔還在不在。還在就照舊續接,不碰存點。
2. 不在、而且有存點 → 跳出確認:「這個節點的對話已經被 <後台> 清除了。要從 <日期> 的存點還原嗎?」列出存點日期與大小。
3. 同意後:檢查 sha256 → 依 `位置` 放回原處(**不覆蓋已存在的檔案**;先寫暫存檔再改名)→ Claude Code 的檔案把修改時間設成現在(否則下次啟動 Claude Code 可能又因為過期被刪)→ 照原本的流程續接。
4. 不在、也沒有存點 → 和現在一樣說明接不回。

Antigravity:只放回 `conversations/` 與 `brain/` 不一定夠(它的對話清單索引在 `conversation_summaries.db`,我們不寫別人的資料庫),所以還原後若續接失敗,提示「Antigravity 的還原是實驗性的」。

### 5. 給寶庫的資料(`.nexus-stats.json`)

每個節點新增 `存點` 清單(新的在前):

```json
"存點": [{ "路徑": "nodes/封存/_存點/<節點ID>/<時間>", "時間": "ISO", "後台ID": "claude", "大小": 123, "原檔還在": false, "可還原": true }]
```

- **欄位型別(S2 定稿)**:`路徑` 字串(相對記憶庫根目錄)、`時間` 字串(帶時區的本機 ISO)、`後台ID` 是 `claude`、`codex`、`antigravity` 之一、`大小` 數字(bytes)、`原檔還在` 是 `true`、`false` 或 `null`、`可還原` 布林。沒有存點時是空清單。說明檔欄位不對的存點不列。
- `原檔還在`:主控台更新統計檔時檢查工具資料夾(每家每 60 秒掃一次建索引)。只有節點**目前那段對話**的存點有值;舊 session 的存點是 `null`(喚醒接回的一定是目前那段,舊的原檔在不在沒有意義)。這是快照:閒置時檔案被清掉,要等下一次統計重寫才反映,真正接回時會再查一次。
- `可還原` = 存點完整(`存點.json` 讀得到)且節點在已終止清單裡、工作目錄還在。原檔還在時寶庫顯示「可直接喚醒」;原檔不在且 `可還原` 時顯示「可從存點還原」;都不是時顯示「只剩紀錄」。
- **和既有欄位的關係(和 vault keeper 對過,2026-11-23)**:
  - `原檔還在` 直接檢查工具資料夾裡有沒有那段對話的主檔(Claude、Codex 的 `<id>.jsonl`,Antigravity 的 `conversations/<id>.db`;快取 60 秒)。`session.CLI有紀錄` 仍是工具自己的對話清單,兩者通常一致;**寶庫顯示存點狀態一律看 `原檔還在` 與 `可還原`,按鈕看 `session.可接回`**。(S2 定稿時由原本「等於 CLI有紀錄」改成直接查檔,較直接也不必等工具的清單。)
  - `可還原` 另外要求存點的 sessionId 是節點目前那段對話的(節點接回後換過 session,舊的存點只列出、不可還原)。在面板上的節點 `可還原` 一律是 false。
  - `session.可接回` 的意思改成「點喚醒會有結果」:原檔還在,或原檔不在但有可還原的存點,都是 true。統計檔與喚醒網址共用 `wake.ts` 的 `canWake`。
  - **分階段**:S3(還原)完成之前,`SAVEPOINT_RESTORE_SUPPORTED` 是 false,`可接回` 與喚醒網址都只看原檔;存點照樣列出、照樣標 `可還原`,只是還不算進 `可接回`。S3 完成後改成 true,兩邊同時生效。寶庫的還原按鈕放在清單裡第一個 `可還原` 為 true 的存點上,條件是 `session.可接回 && 那份的原檔還在 === false`;`原檔還在 === true` 時那份顯示「可直接喚醒」。
  - 喚醒網址不指定存點:主控台一律用**最新一份可還原**的存點;寶庫只在那一份上放還原按鈕,舊的存點只列出來。
  - `工作目錄` 不放進統計檔(本機絕對路徑),只留在 `存點.json`。
  - 封存檔被使用者移走、`_存點` 還在時,統計檔照樣列出存點(寶庫照樣顯示)。
- 寶庫只讀統計檔與封存檔頭,**不讀 `存點.json`、不讀也不預覽 files/ 的內容**;寶庫的掃描本來就跳過所有底線開頭的資料夾。
- 寶庫的「還原」按鈕直接用既有的喚醒網址 `entropy-nexus://wake?node=<節點ID>`:主控台收到後走第 4 節的流程(一定先跳確認)。**不新增任何網路端點**。
- 寶庫端由 vault keeper 實作;格式定稿後由 keeper 寫進寶庫的 `docs/架構.md`(資料格式),顯示文案寫進 DESIGN.md 與 `主控台規格同步清單.md`。

### 6. 隱私與大小

- 存點是**完整的原始對話**,不能遮罩(遮了就無法續接),可能含路徑、程式碼與使用者貼過的資料。只存在本機記憶庫,底線資料夾不給節點讀。記憶庫若被同步到雲端或備份到別處,這些檔案會跟著走;說明檔 `說明.md` 要寫清楚。
- 大小:目前本機三家合計約 2.4 GB(Claude 1.1 GB、Codex 821 MB、Antigravity 440 MB),單一 session 可能數十 MB。第一版不壓縮(還原最單純);單一存點超過 500 MB 時仍然建立,但在刪除結果裡提醒。之後可以加「存點總量」顯示與手動清理。

1. **S1 建立存點**(2026-11-23 完成,`1dfba2b`):三家的檔案定位、複製、`存點.json`、封存檔欄位;單元測試(用暫存的假 `~/.claude` 等資料夾)。
2. **S2 統計檔與寶庫格式**(2026-11-23 完成,格式定稿):`.nexus-stats.json` 的 `存點`;和 vault keeper 對格式。
3. **S3 還原**(2026-11-24 完成;經一次 Opus 獨立審查,5 項必修已修正):接回時檢查原檔、確認對話框、驗證與放回、Claude 修改時間;e2e(假資料模式下用假的 session 檔)。完成後把 `wake.ts` 的 `SAVEPOINT_RESTORE_SUPPORTED` 改成 true(統計檔與喚醒網址在 S2 已共用 `canWake`);一般刪除(IPC `remove`、遠端 `/api/remove`)的存點結果要有通用通知(S1 審查建議 8)。
   - S3 的做法:接回時原檔不在就先問(桌面「開啟舊 session」頁內確認、喚醒網址第二個對話框;手機版不提供,回說明);先驗說明檔、位置白名單與每個檔案的 sha256,再放回;用硬連結放到目的位置(不可能覆蓋),主檔最後放;目的路徑經過連結就不還原;Antigravity 主檔不在但舊 -wal/-shm 還在時不還原;同一段對話同時只接回一次。存在檢查會跟隨 junction(使用者搬過資料夾也算在)。
   - 延後:假資料模式的 e2e;一般刪除(IPC `remove`、遠端 `/api/remove`)的存點結果通知(目前只寫 console);最新一份存點壞掉時改試較舊的;Antigravity 還原後續接失敗時的「實驗性」提示。
4. **S4 真實驗證**:三家各做一次「終止 → 手動刪掉原檔 → 從存點還原 → 續接成功」。Antigravity 結果記錄為實驗性。
