# 節點工作區轉移(規劃)

2026-11-24 使用者要求:研究「用獨立 worktree 建立的節點關閉後重新開啟」的流程,並規劃「轉移節點的工作區域」,先做實驗。本文件是規劃與實驗結果,**還沒有實作**;待使用者裁示第 6 節的問題後開工。

## 1. 現況(讀程式碼的結果)

**獨立 worktree 節點終止時**(`core.ts` 的 removeAgent → `worktree.ts` 的 `removeWorktree(wt, false)`):

| 工作區狀態 | 終止時 | 之後能不能接回 |
|---|---|---|
| 有未提交的修改,或有沒合併的提交 | 保留 worktree 與分支 | 可以 |
| 乾淨、已合併 | **刪掉 worktree 與分支** | **不行**:「原本的工作目錄已經不存在」 |
| 乾淨、從沒提交過(只聊天或看程式) | **也會刪掉**(判斷式 `dirty \|\| ahead > 0` 不成立) | **不行** |

接回(`openOldSession`)第一步就檢查工作目錄存在;1.1.0 的存點也救不了(還原前同樣檢查)。對話檔本身其實都還在。

**轉移工作區**:目前沒有這個功能。`updateAgent` 只能改名稱、角色、模型、權限模式。最接近的是「分支對話」勾「獨立工作區」,但那是另開一個新節點,而且這個組合沒有真實驗證過。

## 2. 實驗結果(2026-11-24,三家各一個子代理,暫存資料夾、最便宜的模型,只清自己建立的對話檔)

| 後台(版本) | 從另一個資料夾續接同一段對話 | 記憶 | agent 實際在哪個資料夾工作 | 對話檔 |
|---|---|---|---|---|
| Claude Code(2.1.330,`-p` 模式) | `--resume <id>` 直接成功(不必搬檔),session id 不變 | 保留 | **新資料夾**:有實際讓它執行 `pwd` 與寫檔,都落在新資料夾;模型也看得到「cwd 從 A 改成 B」的環境提示 | 仍寫回**舊資料夾對應的** `projects/<舊>/<id>.jsonl`;同一份檔案同時存在新舊兩處時,優先用新資料夾那份 |
| Codex(0.171.0-alpha.13,app-server) | `thread/resume { threadId, cwd: 新 }` 成功,thread id 不變 | 保留 | **新資料夾**(模型依環境回報;`turn_context`、`thread_settings_applied` 都帶新 cwd;沒有用工具實測) | 附加在原本的 rollout 檔;檔頭 `session_meta.cwd` 與 `thread/list` 仍是舊資料夾 |
| Antigravity(agy 1.5.13,stream-json) | `--conversation <id>` 成功,舊資料夾刪掉後也成功 | 保留 | **仍以舊資料夾為主要工作目錄**,新資料夾只被加成額外的 workspace;`conversation_summaries.db` 的 `workspace_uris` 不更新 | 存在全域的 `conversations/<id>.db`,不在 workspace 裡 |

其他發現:
- Claude Code 的分支(`--resume <id> --fork-session`)跨資料夾也可行:新 id,新的對話檔寫在新資料夾;原檔不動。
- Codex 的 `thread/fork { cwd: 新 }` 可行:新 thread id,`thread/list` 顯示新資料夾。
- Codex 的 cwd 一定要傳**絕對路徑**(相對路徑會依 app-server 行程解析)。
- 三家都沒有「session 綁定 workspace」的檢查,換資料夾續接不會報錯。

## 3. 設計

### 3.1 功能:轉移工作區

對話視窗的「設定」多一個「轉移工作區」,只有桌面完整權限可以用。目的地三選一:
1. **既有的資料夾**(瀏覽選擇)。
2. **新的獨立工作區**:在某個 git 版本庫開一個新的 worktree(沿用 `createWorktree`)。
3. **重建原本的獨立工作區**(只在原 worktree 已被刪掉時出現):在**原本的路徑**用原分支(分支已刪就從 base)重新 `git worktree add`。

流程(主控台):
1. 前提:最上層節點、待命或休眠、不是終端機模式、沒有進行中的協作流程交辦(流程用的是交辦當時的工作目錄)、不在會議中。佇列暫停到轉移完成。
2. 停掉 session。
3. 更新節點的 `cwd`(與 `worktree` 資訊;移出 worktree 時清掉,移入新 worktree 時填新的)。資料庫要新增更新 cwd 與 worktree 的方法。
4. 用**同一個 sessionId** 在新資料夾續接(三家的轉接器本來就用節點的 cwd 啟動,Codex 的 `thread/resume` 本來就帶 cwd,轉接器不必改)。
5. 在下一則送給節點的指令前面加一則「主控台通知:你的工作目錄已從 <舊> 換到 <新>,之後讀寫檔案與執行指令都以新的資料夾為準。」(沿用身分設定的通知機制;Antigravity 一定要,其他兩家無害)。
6. 對話裡留一則說明(從哪裡換到哪裡、舊的 worktree 怎麼處理)。

**不做的事**:不搬、不改各家工具的對話檔(Claude 的 `projects/`、Codex 的 rollout、Antigravity 的資料庫)。實驗證明不搬也能續接;搬檔等於改別人的資料結構,風險較高。

### 3.2 舊的 worktree 怎麼辦

節點從獨立工作區移出時,舊的 worktree 依現有規則處理:乾淨且已合併才移除,否則保留並在說明裡寫出路徑與分支(和終止時一樣)。或依第 6 節的裁示一律保留。

### 3.3 接回時工作目錄不在了(補上第 1 節的缺口)

`openOldSession` 遇到工作目錄不在時,不再直接拒絕:
- 原本是**獨立工作區**的節點:提供「重建原本的獨立工作區並接回」(3.1 的第 3 種目的地)。
- 其他節點:提供「選一個新的資料夾接回」。
- 一律先問再做(和存點還原同樣的兩段式:第一次回需要確認,使用者同意後才執行)。喚醒網址與「開啟舊 session」都走同一條。

統計檔的 `可接回` 與喚醒網址的判斷要同步調整(工作目錄不在但能重建 worktree 時,算不算可接回 → 第 6 節裁示)。

### 3.4 對其他功能的影響

- **存點**:定位 Claude 的對話檔是掃描整個 `projects/` 找 `<id>.jsonl`,轉移後仍找得到。Codex、Antigravity 不受影響。
- **任務與專案**:轉移後的新任務記在新資料夾的專案;舊任務不變。
- **協作流程**:寫入角色要求節點的 cwd 在專案裡,轉移後會依新 cwd 判斷。
- **開啟舊 session 清單**:Codex 的 `thread/list`、Claude 對話檔裡的 cwd 仍是舊資料夾;主控台以自己記錄的節點 cwd 為準。

## 4. 風險

- **未經文件保證的行為**:Claude 的 `--resume` 跨資料夾搜尋、Codex 的 resume 換 cwd、agy 的 workspace 追加,都是這次在特定版本觀察到的行為,改版可能變動。上線前與每次大版本更新後要重跑真實驗證。
- **Antigravity 仍以舊資料夾為主**:要靠主控台通知提醒;通知後它的檔案與指令工具是否真的在新資料夾執行**還沒驗證**。在驗證前先標實驗性(或暫不開放,見第 6 節)。
- **Codex 的工具**:只驗證了模型回報新 cwd,沒有用工具實測寫檔落在哪裡(Claude 有實測)。
- **舊對話裡的路徑**:轉錄檔與先前的工具輸出仍是舊路徑,模型可能沿用舊路徑;主控台通知可以降低這個風險,不能完全避免。
- **專案設定不跟著走**:舊資料夾的 CLAUDE.md、AGENTS.md、`.agents/` 不會跟過去,新資料夾若有自己的會載入。
- 路徑含空格、中文時 Claude 的資料夾編碼沒有實測(實驗路徑沒有空格);因為不搬檔,影響僅限於理解,不影響功能。

## 5. 里程碑

1. **W1 轉移到既有資料夾或新的獨立工作區**(Claude Code、Codex):主控台流程、資料庫欄位、設定面板、轉移說明與主控台通知;單元測試(只跑相關的)。
2. **W2 接回時工作目錄不在**:重建原本的 worktree 或選新資料夾、先問再做、統計檔與喚醒網址同步。
3. **W3 Antigravity**:加上主控台通知後,用一次有工具的小測試確認檔案與指令落在新資料夾;結果決定開放或標實驗性。
4. **W4 真實驗證**:三家各建一個測試節點,轉移、確認記憶與實際工作的資料夾;worktree 節點終止 → 被刪 → 重建接回。會動真實工具資料夾(只動測試節點自己的),需要使用者授權。
5. 獨立審查在 W2 完成後做一次;測試依目前策略只跑相關的單元測試與 typecheck。
