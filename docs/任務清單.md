## 介面檢查(2026-11-20)

用 `tests/layout.sh`(桌面版)與 `LAYOUT_WEB=1 bash tests/layout.sh`(瀏覽器版完整介面與手機版)自動檢查:在幾種視窗大小下打開主畫面、對話視窗、新增節點和頂部各面板,找出「超出畫面又捲不到」「被容器裁掉」「被其他東西蓋住」的按鈕,以及超出區塊的節點,並截圖。
視窗大小用 CSS 像素:1366×768 螢幕開 125% 縮放約等於 1090×540;1920×1080 開 150% 約等於 1280×650。

### 確認的問題(依嚴重程度)

1. **新增節點的下半部點不到**(你回報的問題):表單直接接在右側欄底部,沒有自己的捲動區。選了角色後角色卡、聲音區塊把表單撐高,在 1100×700 以下,「權限模式、取消、新增」被推到視窗外;在 1090×540 連「工作目錄、瀏覽」也看不到。
   - 修正:表單改成可以捲動(或改成獨立的浮動面板,「取消、新增」固定在底部)。優先 1 拿掉節點清單後,表單本來就要換位置,一起處理。
2. **頂部列在寬度 1240 以下被截斷**:頂部列不會換行或收合,1100 寬時「顯示」「模擬自動運作」在畫面外;瀏覽器版 900 寬時連「?、語音、遠端、快捷鍵」都看不到;整頁還會出現水平捲動。
   - 修正:寬度不夠時把後台標籤(Claude Code 模擬…)縮成圓點、把較少用的按鈕收進「更多」選單;頂部列不允許撐出水平捲動。
3. **待命區的節點擠不下時縮得太小,而且會超出區塊**(你回報的問題):區塊的比例是固定的(待命區只佔寬度的 26%),其他區塊空著也不會讓位。節點多時最小只縮到 45%,還是排不下,就溢出到下方的事件紀錄;即使在 1440×900,13 個待命節點也縮到約 55%,字很難讀。
   - 修正:區塊大小依節點數動態分配(節點多的區塊拿到更多空間);最小縮放提高到 60–65%,真的排不下時顯示「另外 N 個」,點一下列出來,不再溢出。也修正「排得下」的計算沒算到名字與狀態文字的高度。
4. **打開對話視窗後,主面板只剩上方一小條**:1100×700 時,主面板被壓到約 200 像素高,待命區的節點被對話視窗和立繪蓋住、點不到;總管節點也超出自己的區塊。
   - 修正:對話視窗打開時,主面板改用「精簡模式」(只顯示各區塊的節點數和需要處理的節點),或讓對話視窗可以調整高度;立繪不要蓋到主面板。
5. **視窗的最小尺寸寫死 1100×700**:在 1366×768、125% 縮放的筆電上,螢幕可用高度只有約 570–600,視窗比螢幕還高,下緣一定會被工作列或螢幕邊緣切掉。
   - 修正:最小尺寸依螢幕的可用範圍調整(例如最小 960×560),並讓上面幾項在這個尺寸下都正常。

### 沒有問題的部分

- 頂部「語音」「遠端」「顯示」「快捷鍵」「?」面板:內容太長時面板自己可以捲動,按鈕都點得到。
- 手機版:390×844、360×640、844×390(橫放)的節點列表與對話頁,自動檢查都通過,截圖也正常。
